data flow — request ผ่าน Worker
i
ไม่มี KV เพิ่ม — session เป็น signed cookie (HMAC ล้วน, ไม่ query D1 ทุก request) ส่วน rate-limit counter ใช้ D1 ตัวเดียวกับที่เก็บ save อยู่แล้ว
attack vectors → mitigations
⚠
Brute force / credential stuffing บน /login — เดารหัสไม่จำกัดครั้ง
แก้: นับผิดต่อ IP (CF-Connecting-IP, เชื่อได้เพราะ Cloudflare ตั้งที่ edge) ใน D1 — 5 ครั้งผิดใน 15 นาที → ล็อก IP นั้น 15 นาที เช็ค lockout ก่อนแม้แต่จะเทียบรหัส
⚠
Session cookie ปลอม/แก้ไข — cookie เป็น stateless ไม่ query DB ทุก request
แก้: เซ็น payload ด้วย HMAC-SHA256 (SESSION_SECRET ใหม่), ตรวจด้วย timingSafeEqual (ใช้ safeEqual() ที่มีอยู่แล้ว) + เช็ควันหมดอายุ
⚠
Cookie ถูกขโมยผ่าน XSS หรือดักบน HTTP
แก้: HttpOnly (JS อ่านไม่ได้) + Secure (ผูกกับ flag ALLOW_INSECURE_HTTP เดิมที่ใช้กับ HSTS อยู่แล้ว)
⚠
CSRF ที่ /api/save และ /login
แก้: SameSite=Strict — cookie ไม่ติดไปกับ request ข้ามโดเมนเลย ครอบคลุมกรณีใช้งานจริงของแอปนี้ (single-origin)
i
Open redirect ผ่าน ?next=
แก้: รับเฉพาะ path ที่ขึ้นต้นด้วย / ตัวเดียว (ไม่ใช่ //host) ไม่งั้น fallback เป็น /
i
ตาราง login_attempts โตไม่จำกัด
แก้: ลบแถวที่ locked_until หมดอายุแล้วแบบขี้เกียจ (lazy cleanup) ทุกครั้งที่มี POST /login
