สเปกสำหรับ agent · Architecture

Cloudflare Worker เดียว คุมทั้งไฟล์เว็บและ API

ทรัพยากรที่จะสร้าง

  • 01Worker gravship-worker-web — เสิร์ฟไฟล์ static ทั้งหมด + route /api/save
  • 02D1 gravship-d1-main — ตาราง saves(username TEXT PRIMARY KEY, data TEXT, updated_at TEXT)
  • 03Custom domain rim.jairukchan.com ผูกกับ Worker ผ่าน zone jairukchan.com (account SORNKan Co., Ltd.)
  • 04Secrets: AUTH_USER, AUTH_PASS (ตั้งผ่าน wrangler secret put ไม่ hardcode ในโค้ด)

เส้นทางข้อมูล save

  • Aโหลดหน้า → Worker เช็ค Basic Auth → ผ่าน → ส่ง index.html ปกติ
  • Bหน้าเว็บเรียก GET /api/save → Worker query D1 → คืน state ล่าสุด (แทน localStorage)
  • Cทุกครั้งที่ผู้ใช้แก้ค่า → PUT /api/save → Worker upsert แถวใน D1
  • DURL query params ยังทำงานเหมือนเดิม (แชร์ลิงก์ได้) — D1 เป็นแหล่งบันทึกหลักเพิ่มเข้ามา ไม่ใช่แทนที่กลไกเดิมทั้งหมด
สเปกสำหรับ agent · Security

ช่องโหว่ที่ต้องกันไว้ตั้งแต่แรก

1
เดารหัสผ่านซ้ำ ๆ (brute force) — เว็บเปิดสู่อินเทอร์เน็ต ใครก็ยิง request ใส่ endpoint auth ได้ไม่จำกัด
กัน: รหัสผ่านสุ่มยาว ≥16 ตัวอักษร (ตัวเลข+ตัวอักษร) ตั้งแต่แรก ไม่ใช่ค่า default ให้ผู้ใช้ตั้งเอง
2
รหัสผ่านหลุดเข้าโค้ด/GitHub — ถ้า hardcode ใน worker.ts แล้ว push repo public จะเห็นรหัสทันที
กัน: เก็บผ่าน wrangler secret put เท่านั้น, .dev.vars อยู่ใน .gitignore, ไม่มีรหัสจริงในซอร์สโค้ดที่ commit
3
API รับข้อมูลมั่ว/ก้อนใหญ่ผิดปกติ — PUT /api/save เปิดให้ยิง JSON อะไรก็ได้ ถ้าไม่ตรวจจะยัดข้อมูลขยะหรือก้อนใหญ่ลง D1 ได้
กัน: ตรวจ shape ของ field ที่อนุญาต + จำกัดขนาด payload (เช่น ≤ 8 KB) ก่อน upsert, ใช้ prepared statement เสมอ (D1 กัน SQL injection อยู่แล้วถ้าไม่ต่อ string เอง)
!
Basic Auth ไม่มีระบบ rate-limit ในตัว — ยอมรับความเสี่ยงนี้ในสโคปนี้ (เว็บใช้คนเดียว ไม่ใช่ระบบสาธารณะ) ถ้าต้องการเพิ่ม Cloudflare rate-limit rule ทีหลังทำเพิ่มได้โดยไม่กระทบโครงสร้าง
